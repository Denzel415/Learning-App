# Learning App

Denzel's personal learning system. It turns what he reads and watches into short courses, then makes him
retain them with recall, spacing and mixed practice. Decisions live in the course brief ("SQL Course 1 Brief",
a Claude doc); this file is the working context for any coding session.

## How it is built

No build step and no framework. Open `index.html` in a browser and it runs.

- `index.html`: the page when run from this folder. `page.html` is the same page without the outer HTML
  shell, used when publishing to a Claude artifact. Keep the two in step.
- `styles.css`: all styling. The tokens at the top (`:root`) control colors, fonts, radius and spacing.
  Dark theme values are redefined in two blocks below them; change both when changing a color.
- `app.js`: everything else, in sections: settings, scheduler, storage, SQL engine, session, screens, events.
- `courses/sql-1.js`: the course content. One object per unit. The comment at the top explains the fields.
- `data/crm.js`: sample CRM data, generated by `tools/make_data.py`. Edit the script, not the output.
- `vendor/sql-asm.js`: SQLite compiled to JavaScript (sql.js 1.10.3), so queries run in the browser.
- `tools/test.js`: run `node tools/test.js` after changing the scheduler, session builder or course content.

Progress saves to the browser's local storage, and to the artifact's database when published there.

## Rules the app follows (from the brief)

- Attempt first on every new unit, before any explanation.
- The kind of knowledge picks the technique: facts get recall, procedures get worked examples,
  concepts get explained in his own words, lookalikes get mixed practice.
- Feedback names the exact error. Hints come in tiers.
- New units are capped per day. A miss comes back later in the same session and again the next day.
- A chapter ends with a gate: every unit, shuffled, no hints, 80% to pass.
- No demo data or sample deck. Testing a UI change means answering real questions.

## Working agreements

- App changes come from friction noticed during a real session. They are logged in `IMPROVEMENTS.md`
  (he can also save notes inside the app and paste them here).
- Keep the code readable by someone learning front-end: plain HTML, CSS and JavaScript, comments that
  say why, no new dependencies without a reason.
- `notes/` is his knowledge inbox and reference shelf, filed by Claude from a Google Doc he dumps into.
  It doubles as an Obsidian folder. He reads there; he does not write there.
- Write plainly. No filler in UI copy.
